##### Java并发
* 你提到熟悉 Java 并发编程中的锁，比如 synchronized 和 CAS，能说说 synchronized 和 CAS 在实现原理上的核心区别吗？它们分别适用于什么场景？

synchronized是JVM内置锁，通过monitor对象实现，JDK 1.6后引入了锁升级机制（偏向锁→轻量级锁→重量级锁），轻量级锁阶段也会自旋尝试获取锁，仅在自旋失败后才升级为重量级锁（挂起线程）；而CAS是通过Unsafe类的native方法实现的乐观锁，依赖CPU的原子指令，通过循环自旋尝试修改值，不会挂起线程。适用场景上，CAS更适合锁持有时间短、竞争不激烈的场景，此时自旋开销小于线程切换；但CAS存在ABA问题（可通过版本号解决）和自旋过度消耗CPU的问题。synchronized则适合锁持有时间长或竞争激烈的场景，因为此时JVM会升级为重量级锁，通过操作系统调度挂起线程，避免自旋浪费CPU，且无需手动处理ABA等问题，使用更简单稳定


* 关于线程池的corePoolSize、maximumPoolSize、workQueue，能详细说说它们的协作关系吗？比如当任务提交速度远大于线程处理速度时，线程池会如何处理?

1. 若当前线程数＜`corePoolSize`，无论是否有空闲线程，都会创建核心线程执行任务；  
2. 若当前线程数≥`corePoolSize`，则将任务放入`workQueue`：  
   - 若队列未满，任务等待核心线程处理；  
   - 若队列已满，且当前线程数＜`maximumPoolSize`，则创建非核心线程执行任务；  
   - 若队列已满且线程数≥`maximumPoolSize`，则触发拒绝策略。  
当任务提交速度远大于处理速度时：  
- 若使用**有界队列**（如ArrayBlockingQueue），队列满后会创建非核心线程，直到达到`maximumPoolSize`，之后触发拒绝策略；  
- 若使用**无界队列**（如LinkedBlockingQueue），队列会持续堆积任务，此时`maximumPoolSize`失效（不会创建非核心线程），最终可能因任务过多导致OOM。  
此外，非核心线程在空闲时间超过`keepAliveTime`后会被销毁，避免高负载后资源闲置，这也是三者协作中资源动态调整的重要部分。

* 你提到熟悉 Java 并发编程，能说说什么是线程安全吗？在项目中，你是如何保证多线程操作共享资源时的线程安全的？可以结合你做过的项目（比如 DCIM 平台中处理百万级传感器数据的场景）举例说明

线程安全指多线程并发访问共享资源时，无论线程调度顺序如何，程序的执行结果都与单线程执行结果一致，本质是保证操作的原子性、可见性和有序性。

* 关于 Java 中的volatile关键字，你了解它的作用吗？它能保证原子性吗？为什么？
volatile用于修饰变量使得该变量可以在多线程中共享，volatile并不是锁不能保证原子性。
